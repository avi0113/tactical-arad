# ערד · ניהול משימות מבצעיות

מערכת לניהול אירועים, עם שני מאגרים נפרדים:

- **מאגר משימות** — משימות מוכנות מראש. כל משימה ניתנת לעריכה, שכפול ומחיקה בפני עצמה.
- **פעולות לאירוע** — לכל אירוע יש רשימה משלו של הפעולות הנדרשות לביצוע. הוספה מהמאגר יוצרת עותק עצמאי: עריכת המשימה במאגר לא משנה פעולות שכבר נכנסו לאירוע, ועריכת פעולה באירוע לא משנה את המאגר.

הנתונים נשמרים ברשימות SharePoint, לא בקובץ מקומי. אין מסך התחברות; השרת מתחבר ל-SharePoint עם אפליקציה ארגונית.

## רשימות

בפעם הראשונה המערכת יוצרת באתר ארבע רשימות, אם הן עדיין לא קיימות:

| רשימה | תפקיד |
| --- | --- |
| משימות מבצעיות | מאגר המשימות המוכנות |
| אירועים מבצעיים | האירועים |
| פעולות לאירוע | הפעולות הנדרשות בכל אירוע |
| מצב מערכת המשימות | סימון פנימי שהאתר כבר אותחל |

העמודה «מזהה משימת מקור» בפעולה היא טקסט בלבד, לא שדה Lookup. לכן שינוי או מחיקה של משימה במאגר לא משנים פעולה שכבר נוצרה באירוע. אפשר לערוך את הרשימות גם מתוך SharePoint; המערכת קוראת אותן מחדש בכל פעולה.

## חיבור

1. ב-Entra ID יוצרים רישום אפליקציה וסוד לקוח.
2. מוסיפים הרשאת Application של Microsoft Graph: `Sites.ReadWrite.All`, ומאשרים אותה כמנהל. לאתר אחד בלבד אפשר במקום זה `Sites.Selected` ואז להעניק לאפליקציה גישה לאתר.
3. מעתיקים את `.env.example` ל-`.env.local` וממלאים את מזהה הדייר, מזהה האפליקציה, הסוד, וכתובת האתר.

```bash
npm install
npm run dev
```

ואז לפתוח [http://localhost:3000](http://localhost:3000).

באתר ריק נטענים נתוני דוגמה: מאגר משימות עירוני ושלושה אירועים בערד. אם ברשימות כבר יש פריטים, הם נשמרים ולא נדרסים. כפתור «שחזור נתוני דוגמה» מחליף את התוכן בדוגמה.
